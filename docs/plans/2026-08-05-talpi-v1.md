# Talpi v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build talpi v1 — a Claude Code plugin implementing the 0→1 MVP pipeline described in `docs/specs/2026-08-05-talpi-design.md`.

**Architecture:** A prose-first plugin: four skills (`talpispec`, `talpiplan`, `talpirun`, `talpiresume`) plus a session-start hook, with all cross-session state in `.talpi/` Markdown files defined by a single canonical contract doc (`docs/state-format.md`). Talpi's own philosophy is dogfooded: the plugin's *boundaries* (plugin manifest, skill frontmatter, state-file contract) are guarded by POSIX-sh contract tests; the *internals* (skill prose) stay thin and untested.

**Tech Stack:** Markdown skills (Claude Code plugin format, same conventions as `~/code/loopspace`), POSIX `sh` test scripts, no runtime dependencies.

## Global Constraints

- All code, docs, and skill prose in **English** (design doc §6).
- Plugin version starts at `0.1.0`; `plugin.json` and `marketplace.json` versions/descriptions must stay in sync.
- Test scripts are POSIX `sh` (no bashisms), pattern-copied from `~/code/loopspace/scripts/test/*.test.sh`.
- Skill prose never names a specific chat channel (say "report to the human", not "send to Telegram") and never hardcodes the harness beyond Claude Code plugin conventions.
- State files live in `.talpi/` at the target project root; `docs/state-format.md` is the single source of truth for their names and formats — skills may only reference state files defined there (enforced by test).
- Commit after every task (at minimum).

```sh
#!/bin/sh
# Contract test: plugin manifests parse and stay in sync.
set -u
ROOT="$(cd "$(dirname "$0")/../.." && pwd)"

fail() { echo "FAIL: $1"; FAIL=$((FAIL+1)); }
ok()   { PASS=$((PASS+1)); }

P="$ROOT/.claude-plugin/plugin.json"
M="$ROOT/.claude-plugin/marketplace.json"

# 1) Both manifests exist and parse as JSON.
for f in "$P" "$M"; do
  if [ ! -f "$f" ]; then fail "missing $f"

  else ok; fi

# 2) plugin.json has required fields with expected values.
if [ -f "$P" ]; then
  name="$(python3 -c "import json;print(json.load(open('$P'))['name'])" 2>/dev/null)"
  ver="$(python3 -c "import json;print(json.load(open('$P'))['version'])" 2>/dev/null)"

if [ -f "$M" ]; then
  mname="$(python3 -c "import json;print(json.load(open('$M'))['plugins'][0]['name'])" 2>/dev/null)"
  [ "$mname" = "talpi" ] && ok || fail "marketplace.json plugin name != talpi"
fi

echo "manifest.test.sh: $PASS passed, $FAIL failed"
[ "$FAIL" -eq 0 ]
```

```markdown
# .talpi/ State Format

All cross-session state lives in `.talpi/` at the target project root.
Design assumption: any session can die at any moment — these files are
the single source of truth. All files are Markdown, human-readable.

## .talpi/spec.md
Produced by talpispec. Frontmatter-style header line: `status: draft` or
`status: approved` (first line, exactly). Sections, in order:
`# Spec: <project>`, `## Product Picture` (who / core experience / smoke
scenario), `## Requirements`, `## Out of Scope (v1)`,
`## Simplicity Zones`, `## Boundary Contracts` (one `### B<n>: <name>`
per contract, each written testably), `## Reversibility Ledger`
(two subsections: `### Decided (hard to change)` and
`### Delegated (agent's discretion)`).

## .talpi/plan.md
Produced by talpiplan. Header line: `status: draft` or `status: approved`.
Sections: `# Plan: <project>`, then one `## Phase <n>: <name>` per phase,
each containing a goal line, the boundary contracts it pins
(`Contracts: B1, B3` — ids from spec.md), and `- [ ]` task checkboxes.

## .talpi/conventions.md
Drafted by talpiplan, maintained by talpirun (living document). Sections:
`# Conventions`, `## Design Tokens`, `## Shared Utilities`,
`## Layout & Naming`, `## Failure Behavior`. Implementers read this file
before writing code and register new shared utilities here.

## .talpi/state.md
Machine-readable-ish snapshot, overwritten (not appended). Exactly these
keys, one per line: `run_status: speccing | planning | building | done |
halted`, `current_phase: <n>` (0 before build), `phases_total: <n>`,
`updated: <ISO date>`.

## .talpi/journal.md
Append-only event log: `- [<ISO date>] <event>` lines. Never rewritten;
on conflicting entries the latest line wins.

## .talpi/handoff.md
Overwritten at every phase boundary and whenever context runs low:
`## Done so far`, `## Next step`, `## Gotchas`. A fresh session reading
handoff.md + state.md + conventions.md must be able to continue the run
without any conversation history.
```

```sh
#!/bin/sh
# Contract test: every skill satisfies the Claude Code skill format
# and its references/ files are wired both ways.
set -u
ROOT="$(cd "$(dirname "$0")/../.." && pwd)"
PASS=0; FAIL=0
fail() { echo "FAIL: $1"; FAIL=$((FAIL+1)); }
ok()   { PASS=$((PASS+1)); }

[ -d "$ROOT/skills" ] || { echo "FAIL: no skills/ directory"; exit 1; }

for dir in "$ROOT"/skills/*/; do
  s="$dir/SKILL.md"
  base="$(basename "$dir")"
  if [ ! -f "$s" ]; then fail "$base: missing SKILL.md"; continue; fi
  # 1) Frontmatter: first line ---, has name: and description:.
  [ "$(head -1 "$s")" = "---" ] && ok || fail "$base: SKILL.md missing frontmatter"
  grep -q "^name: $base$" "$s" && ok || fail "$base: frontmatter name != dir name"
  grep -q "^description: ." "$s" && ok || fail "$base: missing description"
  # 2) Every references/ file is mentioned in SKILL.md...
  if [ -d "$dir/references" ]; then
    for r in "$dir"/references/*.md; do
      rn="$(basename "$r")"
      grep -q "$rn" "$s" && ok || fail "$base: references/$rn never mentioned in SKILL.md"
    done
  fi
  # 3) ...and every references/*.md mention resolves to a real file.
  for rn in $(grep -oE 'references/[a-z-]+\.md' "$s" | sort -u); do
    [ -f "$dir/$rn" ] && ok || fail "$base: SKILL.md mentions missing $rn"
  done
done

# 4) Channel-neutrality: skill prose never names a specific chat product.
hits="$(grep -rniE 'telegram|slack|discord' "$ROOT/skills" 2>/dev/null)" || true
[ -z "${hits:-}" ] && ok || fail "channel-specific terms in skills:
$hits"

echo "skills.test.sh: $PASS passed, $FAIL failed"
[ "$FAIL" -eq 0 ]
```

```markdown
## Scope Lens
- What is the minimal MVP — the smallest version you would actually use?
- What is explicitly out of scope for v1?
- Which areas are simplicity zones — places you license the agent to keep

- Which decisions in this project will be hard to change later? (Stack,
```

- [ ] **Step 1: Write the talpirun skill**

`skills/talpirun/SKILL.md` frontmatter (verbatim):

```markdown
---
name: talpirun
description: Use when a talpi plan is approved and the build should start or continue. Autonomous per phase - pin boundary contracts as tests first, implement freely inside them, one fresh verifier per phase, non-blocking reports to the human.
---
```

Body — full prose implementing design doc §3.4–3.6, required sections and rules:

- **Guard:** requires `.talpi/plan.md` `status: approved`; else route back.
- **`## Phase loop`** (for the phase in `state.md`'s `current_phase`):
  1. **Thin orchestrator:** the talpirun session never implements inline — it manages state, dispatches one fresh implementer subagent per task, and reports. Each subagent receives `.talpi/conventions.md`, the phase's contracts (`B<n>` shapes from spec), and its task description — no conversation history.
  2. **Pin contracts:** the first task of every phase writes the phase's `Contracts:` list as failing tests before any implementation; journal `phase <n> contracts pinned`.
  3. **Implement freely:** no per-task verification ceremony, no reviewer panels mid-phase. Internal decisions are the implementer's. Subagents return results plus any questions for the human; the orchestrator registers new shared utilities in `.talpi/conventions.md` and relays questions under the routing rule.
  4. **Question routing rule (verbatim in skill):** "Ask the human only what a *user of the product* would notice, or what touches a boundary contract or the Reversibility Ledger's Decided list. Everything else is yours — the ledger's Delegated list is your license."
  5. Contract tests green → phase-end verification.
- **`## Phase-end verification`**: dispatch ONE fresh-context verifier (no conversation history) with `references/verifier-prompt.md`. Fix `[FIX]` findings; carry `[ESCALATE]` findings into the report. Journal `phase <n> verified`.
- **`## Phase report`**: fill `references/phase-report-template.md`, deliver to the human through the session's available channel, journal `phase <n> reported`, update `state.md`, **continue immediately** to the next phase — never wait for a reply. **Exception (blocking escalation):** if a verifier finding alters an entry on the Reversibility Ledger's *Decided* list, set `run_status: halted`, journal `run halted: <reason>`, and let the report ask the human to rule. On ratify: update the ledger and spec, resume. On reject: revert the decision, have a fresh-session verifier re-check the revert, then resume. Every stop-report includes the one-line resume command.
- **`## Persistence discipline`**: rewrite `.talpi/handoff.md` at every phase boundary and whenever context runs low, so any fresh session can continue via talpiresume. State on disk is the only truth; the human is never summoned for context reasons.
- **`## Completion`**: after the last phase — all contract tests green, **smoke run** (launch the product for real and walk the spec's smoke scenario; a broken smoke run reopens the phase loop), then final report asking for human acceptance. `run_status: done`, journal `run done`.

```markdown
Check exactly three things:
1. Contract adherence — does the implementation match the phase's
   boundary contracts, and do the contract tests genuinely pin those
   boundaries (not hollowed out, not testing mocks of themselves)?
2. Smuggled irreversible decisions — schema changes, new external
   dependencies, API shape changes, or anything on the Reversibility
   Ledger's Decided list that was altered without the human. These are
   never yours or the implementer's to settle.
3. Conventions and duplication — violations of conventions.md, logic
   copy-pasted where a shared utility exists or should, values hardcoded
   that the design tokens own.

Do NOT review internal style, structure, or taste beyond what
conventions.md states — internals are licensed to be imperfect; they
only need to remain refactorable.

Report each finding on one line: `[FIX]` (implementer should fix now,
cite the contract or conventions line it violates) or `[ESCALATE]`
```

`hooks/session-start.sh` (POSIX sh, read-only, silent when not a talpi project):

```sh
#!/bin/sh
# SessionStart: if this project has a talpi run, surface its state.
set -u
[ -d ".talpi" ] || exit 0
status="unknown"
[ -f ".talpi/state.md" ] && \
  status="$(sed -n 's/^run_status: *//p' .talpi/state.md | head -1)"
cat <<EOF
This project has a talpi run in progress (run_status: ${status:-unknown}).
Use the talpiresume skill to read .talpi/ state and continue from the
right point. Do not restart the pipeline from scratch.
EOF
exit 0
```
